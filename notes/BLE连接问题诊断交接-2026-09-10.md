## 一、问题现象

手机开启推送服务、车机开启歌词悬浮后：

1. 车机悬浮窗在「已连接，等待放歌」↔「等待手机连接」两个状态间**每约 3.5 秒循环切换**；
2. 手机端监控台在「车机连接断开」↔「正在连接车机」间循环；
3. 歌词始终无法推送成功。

## 二、关键证据（已实锤）

### 证据 1：车机蓝牙栈拒绝手机发起的 MTU 517

车机（Android 9，高通 msmnile 平台）蓝牙栈日志持续报错：

```
E/bt_stack( 1377): [ERROR:gatt_sr.cc(752)] MTU request PDU with MTU size 517
```

每 3.5 秒一次，与断连循环同频。车机栈 GATT_MAX_MTU_SIZE 上限为 512，**手机（ColorOS 一加 PLK110）蓝牙栈把 App 的 requestMtu 请求实际发出为 517**，被车机拒绝。

### 证据 2：断开由手机本地发起（关键）

手机蓝牙栈日志：

```
13:05:52.925  onClientConnectionState() status=0 connected=true device=A4:04:50:0E:98:26
13:05:53.359  GATT_Disconnect: conn_id=202
13:05:53.359  oplus_bta_hh_le: set gatt disconnect action action:1002
13:05:54.391  Disconnected ... reason:GATT_CONN_TERMINATE_LOCAL_HOST   ← 手机主动断
```

即：**连接建立约 1.3 秒后，被手机系统蓝牙栈的 oplus_bta_hh_le（OPPO HID-over-GATT 探查模块）主动掐断**，并级联断开整条 ACL 上所有 GATT 会话（含 IcarLyrics 的）。

### 证据 3：作祟组件

通过 `ps` 定位日志中主动断开 GATT 的进程：

- `com.heytap.accessory`（欢太配件/快连服务，日志标签 PTC.CONN 直接实锤其 GattConnector 断开车机）
- `com.oplus.cardigitalkey`（OPPO 车载数字钥匙）
- `com.heytap.opluscarlink`（OPPO Carlink 车联）
- `com.chery.icar`（奇瑞 iCAR 官方 App，与车机 BLE 配对/管理）

这些组件扫描到车机 BLE 广播后逐个尝试连接探查，发现不是自己要的服务就**强制断开整个 ACL**。

## 三、已验证的有效措施

**临时停用上述 4 个手机应用后：车机 20 秒内 0 次断连**（之前 15 秒 5 次），连接循环停止。

```
adb shell pm disable-user --user 0 com.heytap.accessory
adb shell pm disable-user --user 0 com.oplus.cardigitalkey
adb shell pm disable-user --user 0 com.heytap.opluscarlink
adb shell pm disable-user --user 0 com.chery.icar
```

恢复：将 `disable-user` 换为 `enable` 即可。

> 注意：停用后需重启手机端推送服务（或重启手机）让蓝牙栈清理已建立探查的会话。
